# MiniShop 요구사항 명세서 (SRS)

| 항목 | 내용 |
|---|---|
| 시스템명 | MiniShop — 온라인 도서 주문 |
| 버전 | v1.0 |
| 작성일 | 2026-08-03 |
| Base URL | `http://localhost:4010` |

> 이 문서는 **테스트 설계의 유일한 기준(Test Basis)** 이다.
> 구현(`sut/server.js`)이 이 문서와 다르게 동작하면 그것이 **결함**이다.
> 테스트케이스는 코드가 아니라 반드시 이 문서를 보고 작성한다.

---

## 1. 용어

| 용어 | 정의 |
|---|---|
| 회원 | 이메일/비밀번호로 가입한 사용자 |
| 토큰 | 로그인 성공 시 발급되는 인증 문자열. `Authorization: Bearer <token>` 헤더로 전달 |
| 장바구니 | 회원별로 유지되는 구매 예정 상품 목록 |
| 주문 | 장바구니를 확정하여 재고를 차감한 기록 |

---

## 2. 공통 규칙

### 2.1 응답 형식
- 성공: HTTP 2xx + JSON 본문
- 실패: HTTP 4xx/5xx + `{ "error": { "code": "<코드>", "message": "<설명>" } }`

### 2.2 상태 코드 규약

| 상황 | 코드 |
|---|---|
| 조회 성공 | 200 |
| 생성 성공 | 201 |
| 삭제 성공(본문 없음) | 204 |
| 입력값 검증 실패 | 400 |
| 인증 없음/토큰 무효 | 401 |
| 권한 없음 | 403 |
| 리소스 없음 | 404 |
| 비즈니스 규칙 위반(재고부족 등) | 409 |
| 리소스가 잠김(계정 잠금 등) | 423 |

> **403 주의.** 이 시스템은 "남의 리소스"를 403이 아니라 **404**로 응답한다(FR-08-2).
> 리소스의 존재 여부 자체가 정보 노출이 되기 때문이다. 따라서 403은 현재 v1.0에서
> 사용하는 API가 없다. (SPEC-DEF-002 참조)

### 2.3 인증
- 토큰이 필요한 API에 토큰이 없거나 잘못되면 **401**.
- **로그아웃한 토큰은 즉시 무효화**되어야 한다. (재사용 시 401)

## 3. 기능 요구사항

### FR-01 회원가입 — `POST /api/users`

요청: `{ "email": string, "password": string, "age": number }`

| 규칙 ID | 필드 | 규칙 | 위반 시 |
|---|---|---|---|
| FR-01-1 | email | 필수. `로컬부@도메인.최상위도메인` 형식. 도메인에 점(`.`)이 최소 1개 있어야 한다 | 400 `INVALID_EMAIL` |
| FR-01-2 | email | 이미 가입된 이메일이면 거부 | 409 `DUPLICATE_EMAIL` |
| FR-01-3 | password | 필수. **길이 8자 이상 20자 이하** | 400 `INVALID_PASSWORD` |
| FR-01-4 | password | 영문/숫자를 각각 1자 이상 포함 | 400 `INVALID_PASSWORD` |
| FR-01-5 | age | 필수. 정수. **14 이상 120 이하** | 400 `INVALID_AGE` |

성공: **201** + `{ "id": number, "email": string }` (비밀번호는 응답에 절대 포함하지 않는다)

---

### FR-02 로그인 — `POST /api/auth/login`

요청: `{ "email": string, "password": string }`

| 규칙 ID | 규칙 | 결과 |
|---|---|---|
| FR-02-1 | 이메일/비밀번호 일치 | 200 + `{ "token": string, "user": {...} }` |
| FR-02-2 | 불일치 | 401 `INVALID_CREDENTIALS` |
| FR-02-3 | **연속 5회 실패 시 계정 잠금.** 잠긴 계정은 비밀번호가 맞아도 거부 | 423 `ACCOUNT_LOCKED` |
| FR-02-4 | 로그인 성공 시 실패 카운트는 0으로 초기화 | — |

**상태 전이**

```
[활성/실패0] --실패--> [활성/실패1] --실패--> ... --실패--> [활성/실패4] --실패--> [잠금]
     ^                                                                        |
     |__________________ 성공(카운트 초기화) ______________|                  |
                                                                       (해제 API 없음)
```

---

### FR-03 로그아웃 — `POST /api/auth/logout`
- 토큰 필요. 성공 시 **204**.
- FR-03-1: 로그아웃된 토큰으로 인증 API 호출 시 **401**.

---

### FR-04 상품 목록 — `GET /api/products`

쿼리 파라미터

| 파라미터 | 기본값 | 규칙 |
|---|---|---|
| `page` | 1 | 1 이상 정수. 범위 밖이면 400 `INVALID_PARAM` |
| `size` | 10 | **1 이상 50 이하 정수.** 범위 밖이면 400 `INVALID_PARAM` |
| `keyword` | (없음) | 상품명 부분일치. **대소문자를 구분하지 않는다** |

응답 200: `{ "page": number, "size": number, "total": number, "items": Product[] }`

`Product` = `{ "id": number, "name": string, "price": number, "stock": number, "category": string }`

---

### FR-05 상품 상세 — `GET /api/products/:id`
- 존재하면 200 + Product, 없으면 **404** `PRODUCT_NOT_FOUND`

---

### FR-06 장바구니 담기 — `POST /api/cart` (토큰 필요)

요청: `{ "productId": number, "qty": number }`

| 규칙 ID | 규칙 | 위반 시 |
|---|---|---|
| FR-06-1 | `productId`가 존재해야 함 | 404 `PRODUCT_NOT_FOUND` |
| FR-06-2 | `qty`는 **1 이상 99 이하 정수** | 400 `INVALID_QTY` |
| FR-06-3 | `qty`가 현재 재고를 초과하면 담을 수 없다 | 409 `OUT_OF_STOCK` |
| FR-06-4 | 이미 담긴 상품이면 수량을 합산한다(합산 결과도 FR-06-2/3 규칙을 지켜야 함) | — |

성공: **201** + 장바구니 전체

---

### FR-07 장바구니 조회 — `GET /api/cart` (토큰 필요)

응답 200:
```json
{ "items": [{ "itemId": 1, "productId": 1, "name": "...", "price": 15000, "qty": 2, "subtotal": 30000 }],
  "totalQty": 2, "totalPrice": 30000 }
```
- FR-07-1: `subtotal = price × qty`, `totalPrice = 모든 subtotal의 합`. **totalPrice는 절대 음수가 될 수 없다.**

---

### FR-08 장바구니 삭제 — `DELETE /api/cart/:itemId` (토큰 필요)
- 존재하는 항목: **204**
- FR-08-1: 존재하지 않는 `itemId`: **404** `CART_ITEM_NOT_FOUND`
- FR-08-2: 다른 회원의 항목: **404** (정보 노출 방지를 위해 403이 아닌 404)

---

### FR-09 주문 — `POST /api/orders` (토큰 필요)

요청: `{ "couponCode": string | null }`

**결정표 (Decision Table)**

| 조건 \ 규칙 | R1 | R2 | R3 | R4 | R5 | R6 |
|---|---|---|---|---|---|---|
| 장바구니가 비어있음 | Y | N | N | N | N | N |
| 쿠폰 코드 입력됨 | - | N | Y | Y | Y | Y |
| 쿠폰이 존재함 | - | - | N | Y | Y | Y |
| 쿠폰이 유효기간 내 | - | - | - | N | Y | Y |
| 주문금액 ≥ 쿠폰 최소주문금액 | - | - | - | - | N | Y |
| **결과** | 400 `EMPTY_CART` | 201 정가결제 | 404 `COUPON_NOT_FOUND` | 400 `COUPON_EXPIRED` | 400 `COUPON_MIN_AMOUNT` | 201 할인결제 |

추가 규칙

| 규칙 ID | 규칙 |
|---|---|
| FR-09-1 | 주문 시 각 상품의 재고를 수량만큼 차감한다. **재고는 절대 음수가 될 수 없다** |
| FR-09-2 | 주문 시점에 재고가 부족하면 409 `OUT_OF_STOCK`, 재고는 차감하지 않는다 |
| FR-09-3 | 쿠폰 `minAmount` 비교는 **이상(≥)** 이다. 주문금액이 minAmount와 정확히 같으면 **적용된다** |
| FR-09-4 | 유효기간은 `expiresAt` **당일 23:59:59까지 사용 가능**하다 |
| FR-09-5 | 할인 후 결제금액(`finalPrice`)은 **0원 미만이 될 수 없다.** 할인액이 총액보다 크면 0원으로 처리 |
| FR-09-6 | `RATE` 쿠폰 할인액은 **원 단위 절사(내림)** 한다. 결제금액에 소수점이 남으면 안 된다 |
| FR-09-7 | 주문 성공 시 장바구니는 비워진다 |

성공: **201** + `{ "orderId", "totalPrice", "discount", "finalPrice", "items": [...], "createdAt": string }`

- `createdAt` 은 ISO-8601 문자열이며, FR-10의 "최신순" 정렬 기준이 된다.
  응답에 `userId` 등 내부 식별자를 포함해서는 안 된다.

**쿠폰 마스터 데이터**

| code | type | value | minAmount | expiresAt |
|---|---|---|---|---|
| `WELCOME10` | RATE | 10 (%) | 0 | 2099-12-31 |
| `SAVE5000` | AMOUNT | 5000 (원) | 30000 | 2099-12-31 |
| `BIG50000` | AMOUNT | 50000 (원) | 0 | 2099-12-31 |
| `EXPIRED20` | RATE | 20 (%) | 0 | 2020-01-01 |

## 4. 화면 요구사항 (UI)

| 화면 | 경로 | 요구사항 |
|---|---|---|
| 로그인 | `/` | 이메일/비밀번호 입력, 실패 시 오류 메시지 노출 |
| 상품목록 | `/#/products` | 상품명·가격·재고 표시, 검색, 담기 |
| 장바구니 | `/#/cart` | 수량/소계/총액 표시, 삭제, 쿠폰 입력 후 주문 |

| 규칙 ID | 규칙 |
|---|---|
| UI-01 | 상품명에 HTML 특수문자(`<`, `>`, `&`)가 포함되어도 **문자 그대로** 표시되어야 한다. 예: `HTML <div> 완전정복` 은 화면에도 `HTML <div> 완전정복` 으로 보여야 한다 |
| UI-02 | 금액은 천 단위 콤마와 `원` 단위로 표시한다 (예: `15,000원`) |
| UI-03 | 오류 메시지는 `#message` 영역에 표시한다 |
