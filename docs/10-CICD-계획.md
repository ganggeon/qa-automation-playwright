## 1. 교차 검토 — 세 쪽이 모두 동의한 것

| 항목 | 결론 | 근거 |
|---|---|---|
| **CD(배포 자동화)** | **뺀다** | QA 포트폴리오에 배포는 백엔드/DevOps 영역. QA 면접관의 관심사가 아니다 |
| **Slack** | **맨 마지막 선택 항목으로 강등** | 면접관을 개인 Slack 워크스페이스에 초대할 수 없다. GitHub 기본 기능(상태 배지·PR 체크·Job Summary)이 훨씬 잘 보인다 |
| **순서** | **README 수치 정정이 CI 보다 먼저** | 배지가 초록인데 문서는 168건이면 신뢰도가 깎인다 |

### Gemini 의 추가 판단
- **"CI 가 경쟁력을 획기적으로 올린다"는 과대평가.** 신입~주니어 QA 의 1순위 평가 요소는 여전히 **테스트 설계 논리 + 결함 리포팅**이고, 이미 만든 산출물 6종이 더 중요하다. CI 는 *"이 자동화가 일회성 스크립트가 아니다"* 를 보여주는 **플러스 알파**
- **ROI 1순위 대안**: Actions 실행 후 **Playwright HTML 리포트를 GitHub Pages 로 호스팅.** 이력서 링크 하나로 면접관이 **실패 스크린샷·비디오·trace 까지 브라우저에서 바로** 확인

### 비용 (Codex 추정)

- 4-Job 전체 실행 = Linux runner **약 5~10분** (job 별 분 단위 반올림 + 설치 시간 때문에 로컬 90초보다 훨씬 큼)
- 매일 schedule 만으로 **월 약 150~300분**
- **비공개 저장소 월 2,000분 한도 안. 공개 저장소는 사실상 무제한 무료** → 공개로 하면 비용 문제 자체가 없다
- 조정 여지: 외부 테스트를 주 1회로 축소 / 외부·Newman 은 PR 에서 제외하고 main·schedule 에서만

### git 초보자 사고 우선순위 (Codex)

1. **★★ 잘못된 폴더에서 `git init`** — 경로가 `qa-study-2026-08-31\qa-study-2026-08-03` 으로 **중첩**돼 있다. 한 칸 위에서 초기화하면 다른 학습 자료까지 전부 커밋 후보가 된다. **초기화 전에 반드시 저장소 루트 확인**
2. **비밀값 확인 없이 `git add .`** — Slack webhook 을 파일에 적으면 공개 저장소에 노출. **한 번 커밋된 비밀값은 파일을 지워도 history 에 남는다**
3. `node_modules`·실행 결과 커밋 — 첫 commit 전에 **staged 목록 반드시 확인**
4. `package-lock.json` 누락
5. **README 낡은 수치 공개** — 실제 176건인데 README 는 168건
6. 대소문자 — Windows 는 구분 안 하고 Ubuntu 는 구분한다 (현재 import 는 전부 일치 확인됨)
7. 한글 파일명 + Windows 콘솔 인코딩 — 파일은 UTF-8 정상. 다만 `git status` 에서 깨져 보일 수 있고, **그걸 보고 파일명을 다시 만들면 중복 파일 사고**
8. CRLF/LF 혼합 (위 4번)

### 기타 (Codex)

- `!!process.env.CI` 는 **존재 여부만** 본다 — 로컬에서 `CI=false` 로 둬도 문자열 `"false"` 는 truthy 라 CI 모드가 된다. GitHub Actions 에서는 `CI=true` 라 문제 없음
- 외부 프로젝트의 `retries: 2` 가 전역 CI `retries: 1` 보다 우선
- 아티팩트 업로드는 파일이 없으면 **경고만** 남긴다 → "리포트가 업로드됐다"는 보장이 없다
