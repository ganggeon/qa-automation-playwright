# Newman CI 판정

npm run newman:ci는 기존 컬렉션을 실행하고 원본 검증 실패를 보존한 채 CI 판정을 추가한다.
기존 npm run newman과 컬렉션의 기대값은 변경하지 않았다.

newman:ci는 별도의 새 메모리 SUT를 임의의 로컬 포트에서 시작한다. 기존 서버를 재사용하지 않는다.
실행용 메모리 복사본에서 첫 POST /api/_reset만 GET /api/products 준비 확인으로 바꾼다.
200 응답 검증과 이메일 준비, 나머지 비즈니스 검증은 유지한다. 실행 복사본도 리포트 폴더에 보관한다.
이 서버는 초기화 및 DELETE 요청을 차단한다. 기존 컬렉션 파일과 기존 서버 데이터는 변경하지 않는다.
기존 npm run newman은 여전히 초기화 요청이 있으므로 삭제 금지 지침하에서는 실행하지 않는다.

- BUG-001/006/008의 요청 이름, 검증 이름, AssertionError 메시지 및 실제 HTTP 상태가 모두 일치해야 예상 재현이다.
- 현재 검토된 범위는 요청 14개, 검증 28개다. 범위 변경도 검토가 필요하다.
- 새로운 실패, 실행 오류, 누락/건너뜀, 기존 기대 실패의 소멸은 CI 실패로 알린다.
- 결함을 수정한 경우 제품 수정과 회귀 검증의 증거를 확인한 뒤 알려진 결함 목록과 해당 테스트를 함께 갱신한다.
- 예상 재현 판정은 제품 결함 해결이나 릴리스 승인이 아니다.

결과는 reports/newman/실행시각-PID/에 새로 저장한다.
results.json과 index.html은 원본 실패를 담고, verdict.md와 GitHub Job Summary는
미해결 결함 ID 및 판정 이유를 보여준다. 이전 리포트를 삭제하지 않는다.

로컬 검증: node --test utils/newman-verdict.test.js
임시 로컬 HTTP 서버와 실제 Newman 결과 직렬화를 포함하며, 제품 데이터는 초기화하지 않는다.

실제 SUT 검증: npm run newman:ci (별도 서버 기동 불필요).
2026-09-11 로컬 결과: 14요청 / 28검증 / 알려진 실패 3건, 판정 종료 코드 0.
이는 준비 확인을 포함한 실행이며 기존 초기화 API 자체를 검증한 결과는 아니다.
